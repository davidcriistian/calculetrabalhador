# Central Brain — Rule Update Manual

## Required inputs

- canonical rule ID;
- official source reference;
- effective date;
- legal reviewer;
- requested change type;
- change rationale;
- expected consumers.

## Workflow

1. Verify the official source.
2. Record the current rule fingerprint.
3. Prepare a proposal; do not edit public consumers directly.
4. Run the governed impact analyzer.
5. Review calculators, articles, clusters, nuclei and pillar pages.
6. Obtain approvals from domain owner, legal reviewer and publishing owner.
7. Build the controlled execution plan.
8. Confirm rollback availability.
9. Generate preview and evidence.
10. Run structural, regression and end-to-end validations.
11. Apply only approved patches in a controlled environment.
12. Record the resulting audit event.

## Prohibited actions

- direct silent edits to rules;
- automatic article rewrites;
- automatic publication;
- guessing unresolved paths;
- skipping legal review;
- publishing with failed validators.
